# 포장 라벨 제조일 누락 호환 처리 — 2026-09-29

## 원인

포장 출력은 `heatTreatmentHistory[].completedAt`만 읽었습니다. 과거 열처리 코드에는 완료 시 공정/배정 상태만 이동시키고 완료일을 WIP에 저장하지 않던 버전도 있었습니다. 이전 667 복구 로트 예외는 해당 한 건에만 적용돼 다른 과거 로트에는 효과가 없었습니다.

## 처리

- 구조화된 열처리 이력, 명시적인 열처리 완료/배치 필드, `details`의 날짜가 있는 `[열처리완료]`/`[열처리 완료]` 이벤트에서 최신 완료일을 선택합니다.
- ISO/Firestore 타임스탬프는 한국 날짜로 정규화합니다. 불가능한 날짜와 미래 날짜는 사용하지 않습니다.
- LOT 번호, 배합/생성일, 수축률 측정일, 포장일, 출력일을 제조일로 추정하지 않습니다.
- 원기록을 찾지 못하면 포장 행에서 실제 완료일·확인 근거·담당 작업자를 입력할 수 있습니다. 출력 성공 시 라벨 제조일 확인 기록을 별도로 남깁니다.
- 확인 날짜를 열처리 이력으로 만들어 넣지 않습니다. 기존 수량/공정/수축률/생산·포장 LOT/과거 이력은 보존됩니다.
- 출력 요청·확인 기록·출력 이력은 한 트랜잭션으로 저장됩니다. 실패하면 모두 저장하지 않습니다. 동시 날짜 변경은 출력 전에 차단합니다.
- 새 출력 이력에는 제조일을 저장하며, 출력 뒤 실제 제조일 기록이 변경되면 포장완료 전에 재출력합니다. 과거 출력 이력만 있는 정상 로트의 완료 조건은 유지합니다.
- 기존에 승인된 667 제조일은 원래 조건 그대로 유지합니다. 빌드 패치는 새 공통 함수가 있으면 중복 적용하지 않습니다.

- 56·44·50·48개 출력 수량, 기존 수량/단계/이력 보존, 출력 실패 시 확인 기록 미저장 확인.
