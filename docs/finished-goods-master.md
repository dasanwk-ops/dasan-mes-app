# 완제품 현황 상세 (마스터)

## 사용 위치

마스터 PIN으로 접속한 뒤 **대시보드 → 공정 진행 현황 상세 아래 → 완제품 현황 상세 (마스터)**를 사용합니다.
상단 `출고대기 완제품` 카드를 누르면 이 영역으로 스크롤됩니다.

`최종 포장 LOT / 생산 MIX LOT / 제품 / 현재고 / 수량 정정 / 이력`을 표시합니다.
LOT·제품 검색, 제품 필터, `재고 0 포함`을 지원합니다.

## 수량 정정

1. 해당 최종 포장 LOT의 `수량 정정`을 누릅니다.
2. 변경할 **현재고**와 필수 정정 사유·처리자 이름을 입력합니다.
3. 변경 전후 수량과 증감량을 확인하고 `정정 저장`을 누릅니다.
4. 완제품 창고와 대시보드는 같은 `wipList`의 `currentStep === "done"` 재고를 사용합니다.

공용 PIN/익명 Firebase 인증이므로 실제 처리자 이름은 자동 식별할 수 없습니다.
이름은 직접 입력하며 접속 UID, 한국 시간 표시 일시, 서버 생성 시각은 함께 기록됩니다.

## 저장 범위와 안전장치

- 한 Firestore 트랜잭션에서 대상 완제품 문서의 `qty`와 정정 메타데이터를 갱신하고
  같은 데이터 경로의 `finishedGoodsAdjustments` 컬렉션에 별도 이력을 생성합니다.
- `beforeQty`, `afterQty`, `deltaQty`, 사유, 이름, 접속 UID, 포장/MIX LOT, 처리일시를 저장합니다.
- 기존 원재료, 과거 공정 상세기록, 포장 완료일, 라벨 출력 이력, 출고 이력을 수정하지 않습니다.
  라벨 큐를 생성하지 않으며 기존 공정 되돌리기·수량 정정·삭제 기능은 유지합니다.
- 수량 변경에 따른 대시보드/발주 진행률 등 기존 집계 로직의 재계산은 그대로 동작합니다.
  이 기능이 과거 모든 연결 집계값을 고정하는 것은 아닙니다.
- 저장 전 최신 LOT·제품·수량·정정 버전을 다시 확인합니다. 동시 출고/정정으로 변경되면
  자동 덮어쓰기 대신 다시 확인하도록 막습니다. 동일 요청 재시도는 이력을 중복 생성하지 않습니다.
- 수량 0 정정은 문서를 삭제하지 않습니다. 기존 전량 출고 로직이 문서를 삭제한 LOT는
  출고·정정 이력으로 조회만 하며 자동 재생성하지 않습니다.
- 여러 재고 문서가 같은 포장 LOT를 공유하거나 제품 연결이 충돌하면 합계는 표시하되 정정을 막습니다.
- 정정 이력 조회가 실패하면 오류를 표시하고 정정 저장을 막습니다.
- 별도 마이그레이션이나 기존 데이터 자동 보정은 추가하지 않습니다. 화면을 여는 것만으로
  새 정정 기능이 재고를 쓰지 않습니다. 기존 앱의 자동 발주 정합성 처리 등은 변경하지 않습니다.

## 과거 기록 표시

포장 완료 당시 수량이 기록되지 않은 기존 LOT는 `미기록`으로 표시합니다.
현재고/라벨 장수로 과거 입고수량을 추정하여 사실처럼 표시하지 않습니다.
출고 기록의 기존 수량 필드가 없는 경우도 `미기록`을 유지합니다.
재고 0 포함은 전량 출고된 LOT의 이력 조회용이며 재고 복구 기능이 아닙니다.

## 통합 방식

이 저장소의 기존 `tools/apply-*.cjs` 방식에 맞춰,
`start`와 `build`에서 `apply-finished-goods-master.cjs`가 대시보드에 독립 컴포넌트를 연결합니다.
반복 실행은 멱등이며 앵커 불일치 시 부분 수정을 쓰지 않고 중단합니다.
기존 App의 생산·출고 함수는 변경하지 않습니다.

## 검증

- `node tools/test-finished-goods-master.cjs`: 수량 검증, LOT 구분, 이력, 원자적 저장 계획,
  저장 실패/동시 출고/재시도 및 기존 공정 함수 보존.
- `node tools/test-finished-goods-ui.cjs`: 마스터/작업자 노출, 검색, 재고 0 조회,
  취소, 56→57 정정, 이력, 편집 중 수량 변경, 조회 오류, 구독 해제.
- GitHub Actions: 기존 열처리·라벨 회귀검사 및 실제 production build.
- 모든 자동 검사는 합성 데이터/가짜 Firebase를 사용합니다. 운영 재고에는 쓰지 않습니다.

## 배포 전후 확인

기존 PIN 접근 제어와 Firestore 보안 규칙은 이번 변경에서 수정하지 않습니다.
클라이언트 `isAdmin` 검사는 기존 화면 권한 모델을 유지하는 것이며
서버 수준의 신규 역할 인증을 구현한 것은 아닙니다.
운영 규칙에서 `finishedGoodsAdjustments` 조회·생성이 허용되는지 실제 계정 확인이 필요합니다.
권한을 임의로 완화하지 않습니다. 이력 조회에 실패하면 새 화면에 명시적으로 표시됩니다.

기존 전체 백업 도구는 컬렉션을 재귀 탐색하므로 새 이력 컬렉션을 위한 고정 목록 수정은 필요하지 않습니다.
자동 검증 통과는 실제 운영 계정 권한 및 태블릿/프린터 현장 확인을 대체하지 않습니다.

이번 기능 추가 자체로 `F260928001`의 운영 재고를 56→57로 변경하지 않습니다.
배포와 화면 확인 후 관리자가 사유·이름을 입력해 정정합니다.
